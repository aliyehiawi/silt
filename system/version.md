# Convention version

**Current:** `1.0` (2026-04-25)

The four-rule graph convention defined in [[memory/README.md|Memory README]] § "Graph convention". When this version bumps, every vault file's frontmatter / wiki-link form may need a migration; the script in [[system/scripts/transform.py|system/scripts/transform.py]] is the canonical migrator.

## Version history

### 1.0 — 2026-04-25 — Initial public convention

- Path-based wiki-links: `[[<path-from-vault-root>|<display>]]`
- YAML frontmatter required on every `.md` file (`type`, `title`, `created`, `updated`, `tags`)
- `## Linked from` footer auto-regenerated by `transform.py`
- Spine files (CLAUDE.md, AGENTS.md, indexes, SKILLs, hubs) filtered from inbound backlink computation
- Rule 4 ("link entities to each other, not just through TOCs") explicitly enshrined
- Folder layout: `system/` for transferable kit, `memory/` for curated knowledge, `journal/` for immutable log
- Scripts: `transform.py` (idempotent rewriter), `audit.py` (read-only diagnostic), `repair_links.py` (broken-link fixer)
- Test suite at `system/scripts/tests/`

## Migration policy

If a future version (e.g. `2.0`) changes the wiki-link format or the frontmatter shape, the migrator in `transform.py` must:

1. Detect the existing convention version from this file (or from frontmatter on each file).
2. Apply transformations idempotently — running it twice should be a no-op.
3. Update this file's `Current` line and add a "Version history" entry.
4. Run the test suite at `system/scripts/tests/` to catch regressions.

If you're forking, treat this file as the contract. Don't change the convention without bumping the version and writing a migrator.
